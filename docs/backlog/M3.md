## S-20 · React "Fisgou" to a catch

**Type** Story · **Milestone** M3 · **Workstream** C · Social · **Priority** Must · **Size** S · **Journey** J4
**Depends on** {{S-11}} · **Blocks** {{S-30}}

### Story
As a friend, I want to react to a catch with one tap, so that I can cheer someone on quickly.

### Context
One reaction type, "Fisgou" ("Hooked") with Lucide's `fishing-hook` icon. Social actions never give XP.

### Scope
- In: `reactions` table, toggle command, counter, optimistic UI.
- Out: the notification itself (S-30 subscribes to the event).

### Implementation notes
- Table `reactions` (`social/schema.ts`): `post_id`, `user_id`, `created_at`; PK on both.
- `posts.reaction_count` int, updated in the same transaction.
- Command `social.toggleReaction({ postId })` (tx, rate limit 300 per hour): `canViewPost` else NOT_FOUND; insert or delete; adjust the counter; on insert, `emit(tx, { type: 'ReactionAdded', postId, actorId, ownerId })` unless reacting to your own post.
- UI: the button in `CatchCard` and on the post page; `useOptimistic` flips state and count immediately and rolls back on error with a toast ("Não deu para salvar. Tente de novo.").
- `hydratePosts` includes `viewerReacted`.

### Acceptance criteria
- [ ] Given I tap "Fisgou", then the icon turns `bobber-text` and the count goes up at once, and it's still there after a reload.
- [ ] Given I tap again, then it's removed.
- [ ] Given 20 fast taps, then the stored state matches the last tap and the count is correct.
- [ ] Given a post I can't see, then the command returns NOT_FOUND.
- [ ] Given any reaction, then no row is added to `xp_events`.

### Tests
- Integration: toggle, counter consistency under parallel toggles, visibility, no XP.
- E2E: part of J4.

## S-21 · Comment on a post

**Type** Story · **Milestone** M3 · **Workstream** C · Social · **Priority** Must · **Size** S · **Journey** J4
**Depends on** {{S-12}} · **Blocks** {{S-28}}, {{S-30}}

### Story
As a friend, I want to comment on a catch or post, so that we can talk about it in the app.

### Scope
- In: `comments` table, add and delete, comment list, safe link rendering.
- Out: threads, editing, mentions.

### Implementation notes
- Table `comments`: `id`, `post_id`, `author_id`, `body` (1–1,000 characters), `created_at`, `hidden_at`, `deleted_at`. Index (`post_id`, `created_at`).
- `posts.comment_count` maintained in the transaction (only visible comments).
- Commands: `social.addComment({ postId, body })` (tx, rate limit 60 per hour, `canViewPost`), emits `CommentAdded { postId, commentId, actorId, ownerId }`; `social.deleteComment({ commentId })` (author, or the post's owner, or a platform admin).
- Rendering: plain text with line breaks; URLs turned into links with `rel="nofollow ugc noopener"` and `target="_blank"`; no HTML ever.
- Post page: list (oldest first, 50 at a time with "Ver mais"), composer at the bottom (sticky on mobile), author avatar and name, relative time.
- i18n namespace `comments`.

### Acceptance criteria
- [ ] Given a comment with a link, then the link opens in a new tab and the text otherwise renders as typed, including `<b>` shown literally.
- [ ] Given I delete my comment, then it disappears and the count drops.
- [ ] Given the post's owner, then they can delete others' comments on their post.
- [ ] Given a 1,001-character comment, then the form and server reject it.

### Tests
- Unit: link rendering and escaping.
- Integration: add, delete permissions, counter, visibility.

## S-22 · Share a tip

**Type** Story · **Milestone** M3 · **Workstream** C · Social · **Priority** Must · **Size** M
**Depends on** {{S-07}}, {{S-11}} · **Blocks** {{S-23}}

### Story
As an experienced angler, I want to share a tip about gear, bait, technique or a recipe, so that what I know reaches others.

### Context
Tips carry the fishing knowledge the culture pitch is about. They're a kind of post, so they reuse feeds, comments, reactions, audience and moderation. They give no XP.

### Scope
- In: the tip post kind, the composer, the tips list with category filters.
- Out: filtering by species and place on the list (nice to have if time remains inside this item, otherwise later).

### Implementation notes
- `posts` columns used: `kind = 'tip'`, `title` (3–80), `body` (≤ 4,000), `tip_category` (`equipment` | `bait` | `technique` | `recipe` | `other`), `tip_species_id` nullable, `tip_place_id` nullable, `link_url` nullable (https only, ≤ 500, shown with its domain).
- Command `social.createPost({ kind: 'tip', … , groupIds, isPublic, mediaIds })` (tx, rate limit 30 per day): validates membership, links media (0–4 photos through S-07), emits `PostPublished`.
- Composer `/post/new?kind=tip`: category chips with the fixed colors (Equipamento water, Isca bobber, Técnica gold, Receita reed, Outro neutral), title, body, optional photos, optional link, optional species (picker) and place, audience.
- Tips appear in feeds with a `TipCard` (category chip, title, first lines, photo).
- `/groups/[id]/tips` and a "Dicas" filter on the public feed: category chips.
- i18n namespace `tips`.

### Acceptance criteria
- [ ] Given a tip with category Isca and a photo, then it shows in my group's feed with the red category chip.
- [ ] Given the tips list filtered by Receita, then only recipe tips show.
- [ ] Given a link starting with `javascript:`, then it's rejected.
- [ ] Given a tip, then no XP is awarded.

### Tests
- Unit: Zod schema (link scheme, lengths, category).
- Integration: create with media and audience; no XP; filter query.

**Depends on** {{S-11}} · **Blocks** {{S-40}}

### Story
As an angler, I want to see public catches from other anglers, so that I discover fishing beyond my group.

### Implementation notes

- Empty states per tab.

### Acceptance criteria
- [ ] Given I'm in two groups, then "Meus grupos" merges both without duplicates when a post is shared to both.
- [ ] Given a hidden public post, then it never appears in "Público".
- [ ] Given 100 public posts, then pagination works with no duplicates or gaps.

### Tests
- Integration: merged-groups dedup; public index used (check `explain` in the test or the PR); hidden excluded.

## S-26 · Create a group challenge

**Type** Story · **Milestone** M3 · **Workstream** B · Gamification · **Priority** Must · **Size** M · **Journey** J3
**Depends on** {{S-04}}, {{S-13}} · **Blocks** {{S-27}}, {{S-39}}

### Story
As a group admin, I want to create a challenge from a template, so that our group has a goal for the month.

### Context
Challenges come from templates, never from a free-form rule builder. Monthly challenges give a short rhythm inside the quarterly season.

### Scope
- In: `challenges` table, templates with parameter schemas, create, edit while scheduled, cancel, list.
- Out: scoring and finalization (S-27), official challenges (S-39).

### Implementation notes
- Table `challenges` (`gamification/schema.ts`): `id`, `scope` (`group` | `official`), `group_id` nullable, `created_by`, `template`, `title`, `params` jsonb, `starts_on`, `ends_on` (dates, Brasília time), `min_verification` (`reported` | `photo_ai_match`), `status` (`scheduled` | `active` | `finalizing` | `finished` | `cancelled`), `finalized_at`, `created_at`.
- Templates in `gamification/challenges/templates.ts`, each with a Zod schema for `params`:
  - `most_species`: distinct species.
  - `heaviest`: max `weight_g`.
  - `longest`: max `length_mm`.
  - `species_goal`: `{ speciesIds: string[] (2–10), target: number }`, complete or not.
  - `most_released`: count of released catches.
  - Shared filters: `speciesIds?`, `waterTypes?`, `releasedOnly?`.
- Status is derived from dates by a pure function and also stored by the daily job; queries use the derived value so status is never stale.
- Commands: `gamification.createChallenge` (group admin; `starts_on ≥ today`, length 1 day to 3 months; rate limit 10 per day), `updateChallenge` (only while scheduled), `cancelChallenge` (until finished).
- When a challenge starts (creation day, or the daily job on `starts_on`), notify members with `challenge_started`.
- UI: `/groups/[id]/challenges` (active, upcoming, past) and `/groups/[id]/challenges/new`: template cards with an example sentence, auto-filled title (editable), dates, filters. `ChallengeCard` from the design system.
- i18n namespace `challenges` (templates have a name and a sentence each, with placeholders).

### Acceptance criteria
- [ ] Given an admin creating "Mais espécies em novembro" for 1–30 Nov with released fish only, then it shows as active to every member with the rule sentence.
- [ ] Given a member who isn't admin, then the create button doesn't show and the command returns FORBIDDEN.
- [ ] Given a scheduled challenge, then the admin can edit it; once active, only cancel.
- [ ] Given a `species_goal` with one species, then validation fails.

### Tests
- Unit: each template's params schema; status derivation around midnight in Brasília time.
- Integration: create, edit, cancel permissions; member notification at start.

## S-27 · Compete on a challenge leaderboard

**Type** Story · **Milestone** M3 · **Workstream** B · Gamification · **Priority** Must · **Size** M · **Journey** J3
**Depends on** {{S-26}}, {{S-16}} · **Blocks** {{S-39}}, {{S-44}}

### Story
As a member, I want a live leaderboard and a final result, so that the challenge feels fair and finished.

### Context
Scores are computed by SQL when the leaderboard is read. A daily job finalizes challenges after a 48-hour grace period, saves results and awards placement XP. Running the job twice must change nothing.

### Scope
- In: scoring per template, the leaderboard page, the daily job and its heartbeat, finalization, placement XP, unattached media cleanup and old-notification cleanup in the same job.
- Out: official challenge specifics (S-39).

### Implementation notes
- `scoreChallenge(challengeId)`: catches by current group members (or participants, for official ones) where `caught_on` within the dates, `created_at ≤ ends_on + 48h`, not deleted, visible to the group (shared with it, or public), matching the filters, and `verification_level ≥ min_verification`. Score per template; ties go to whoever logged the scoring catch first.
- Page `/challenges/[id]`: `ChallengeCard` header (rule, time left, participants), `LeaderboardRow` list with each person's score in the template's unit (species, kg, cm, fish released), my row highlighted, the scoring catch linked.
- Daily job: `src/app/api/cron/daily/route.ts`, scheduled in `vercel.json` at 06:00 UTC (03:00 Brasília), requires `Authorization: Bearer ${CRON_SECRET}`. Tasks, each idempotent and each logged:
  1. Finalize challenges with `ends_on + 48h < now` and status not finished: in one transaction, snapshot `challenge_results` (`challenge_id`, `user_id`, `rank`, `score`), award XP through the ledger (`source_type = 'challenge'`, key `challenge:<id>:<userId>`): 150 / 100 / 75 for 1st–3rd, 50 for completing a `species_goal`; only when at least 3 people scored; capped at 600 challenge XP per angler per season; set `finished`; notify participants with `challenge_result`.
  2. Notify `challenge_started` for challenges starting today.
  3. `media.cleanupUnattached(24)`.
  4. Delete notifications older than 90 days.
  5. On success, `GET ${HEALTHCHECKS_PING_URL}`; on failure, `GET ${HEALTHCHECKS_PING_URL}/fail` and rethrow (Sentry catches it).
- Healthchecks.io check: period 1 day, grace 2 hours, Discord `#alerts` integration.

### Acceptance criteria
- [ ] Given a running "heaviest fish" challenge, when a member logs a heavier qualifying catch, then the leaderboard shows the new leader on the next load.
- [ ] Given a catch logged 30 hours after the end with a fishing date inside the window, then it counts; at 50 hours, it doesn't.
- [ ] Given only two people scored, then results are saved but no XP is awarded.
- [ ] Given the daily job run twice in a row, then XP and results are unchanged by the second run.
- [ ] Given the job fails, then the Healthchecks fail ping and a Sentry issue are sent.

### Tests
- Unit: scoring for each template with filters and ties.
- Integration: finalization idempotency; 3-scorer rule; the 600 cap; grace period.
- E2E (J3): admin creates a challenge, a member logs a qualifying catch, the leaderboard updates.

## S-28 · Report a post, comment or profile

**Type** Story · **Milestone** M3 · **Workstream** C · Social · **Priority** Must · **Size** S
**Depends on** {{S-21}} · **Blocks** {{S-29}}, {{S-39}}

### Story
As a member, I want to report something abusive, so that the community stays a good place.

### Context
Three counted reports hide content until review. To stop throwaway accounts from hiding anyone's posts, only accounts at least 3 days old with at least one catch count.

### Implementation notes
- Table `reports` (`moderation/schema.ts`): `id`, `reporter_id`, `subject_type` (`post` | `comment` | `profile`), `subject_id`, `reason` (`spam` | `abuse` | `inappropriate` | `fake_catch` | `other`), `note` (≤ 300), `counted` (bool), `created_at`, `resolved_at`, `resolution`. Unique (`reporter_id`, `subject_type`, `subject_id`).
- Table `moderation_actions`: `id`, `actor_id` (null for the system), `action` (`auto_hide` | `hide` | `restore` | `remove` | `remove_from_group`), `subject_type`, `subject_id`, `group_id` nullable, `reason`, `created_at`. Append-only (revoke update and delete from `app_server`).
- Command `moderation.report({ subject, reason, note })` (rate limit 20 per day): the reporter must be able to see the subject; `counted` = account ≥ 3 days old and ≥ 1 catch; when counted reports on an unresolved subject reach 3, set `hidden_at` on it (posts, comments; profiles get `hidden_at` too) and write `auto_hide`.
- Hidden content disappears from feeds and pages for everyone except its author (who sees "Em revisão").
- UI: "Denunciar" in the menu of posts, comments and profiles; a sheet with the reasons and an optional note; confirmation "Obrigado, vamos revisar."

### Acceptance criteria
- [ ] Given three reports from eligible accounts, then the post disappears from feeds and its author sees "Em revisão".
- [ ] Given three reports from accounts created today, then nothing is hidden.
- [ ] Given I report the same post twice, then the second is refused politely.

### Tests
- Integration: counting rules, auto-hide, uniqueness, author view of hidden content.

## S-29 · Review reports

**Type** Story · **Milestone** M3 · **Workstream** A · Platform · **Priority** Must · **Size** M
**Depends on** {{S-28}} · **Blocks** nothing

### Story
As a platform admin, I want a queue of reported content, so that I can restore or remove it quickly.

### Implementation notes
- Table `platform_admins` (`user_id`); the viewer's `isPlatformAdmin` comes from it.
- `/admin/reports` (platform admins only, else 404): subjects with open reports, newest first; each shows the content (even if hidden), author, report count, reasons and notes, counted or not.
- Actions: Restore (clear `hidden_at`, resolve reports as `dismissed`), Remove (`deleted_at`, resolve as `removed`), Dismiss reports without changing visibility. Each writes `moderation_actions`.
- Group admins: "Remover do grupo" on any post in their group deletes that `post_groups` row, writes `remove_from_group` and emits `AudienceChanged`.
- Notify the author when their content is removed (`content_removed`, no reporter names).

### Acceptance criteria
- [ ] Given a hidden post, when an admin restores it, then it's back in feeds and the reports are resolved.
- [ ] Given a group admin removing a post from their group, then it leaves that group's feed and ranking but stays in other audiences.
- [ ] Given a non-admin opening `/admin/reports`, then they get 404.
- [ ] Given any of these actions, then a `moderation_actions` row records who did what.

### Tests
- Integration: each action and its audit row; group admin scope limited to their group.

## S-30 · Get notified about social activity

**Type** Story · **Milestone** M3 · **Workstream** C · Social · **Priority** Must · **Size** S · **Journey** J4
**Depends on** {{S-18}}, {{S-20}}, {{S-21}}, {{S-05}} · **Blocks** nothing

### Story
As an angler, I want to know when someone reacts, comments, follows me or joins my group, so that I can respond.

### Implementation notes
- Handlers in `notifications/events.ts`:
  - `ReactionAdded` → owner gets `reaction` (one per actor per post, ever; un-react and react again doesn't notify again).
  - `CommentAdded` → owner gets `comment` (not for their own comments).
  - `MemberJoined` → group admins get `member_joined`.
  - `Followed` → followee gets `follow` (S-40 emits it).
- Coalesced rendering in the list: "Kauê e mais 3 fisgaram sua tilápia" when several reactions on the same post arrive the same day.
- Each links to the relevant page.

### Acceptance criteria
- [ ] Given three friends react to my catch, then I see one coalesced line naming the first and the count.
- [ ] Given I react to my own catch, then I get nothing.
- [ ] Given someone joins my group, then the admins are notified.

### Tests
- Unit: coalescing.
- Integration: each handler, including the "only once per actor" rule.
