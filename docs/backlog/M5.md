## S-38 · Share a catch to WhatsApp with a preview

**Type** Story · **Milestone** M5 · **Workstream** C · Social · **Priority** Should · **Size** M · **Journey** J7
**Depends on** {{S-12}}, {{S-14}} · **Blocks** nothing

### Story
As an angler proud of a catch, I want to share a link that looks good in WhatsApp, so that friends outside the app see it and join.

### Context
This is the growth loop and the culture pitch's "circulation beyond the group". Only public catches get a rich preview; anything else stays behind 404.

### Implementation notes
- `/p/[id]` works signed out for public posts (already allowed by the proxy list from S-01): same page without reaction or comment input, plus a banner "Pescou algo? Entre no Pesqueiro.GG" linking to sign-up.
- `src/app/p/[id]/opengraph-image.tsx` with `ImageResponse` (1200×630): the catch photo on the left, species name in the display font, rarity badge, author's handle, the logo. Fonts loaded as data for the image. Non-public posts get a generic brand image.
- Metadata: `og:title` "Tucunaré-açu de @amanda", `og:description` facts line, `og:image`, Portuguese (WhatsApp's crawler sends no useful language).
- Share button on the post: Web Share API with the URL plus `?s=1`; fallback copies the link.
- Table `share_opens` (`post_id`, `day`, `count`): incremented when a signed-out visitor opens `?s=1` (feeds S-35's number). No IP or user agent stored.

### Acceptance criteria
- [ ] Given a public catch link pasted in WhatsApp, then the preview shows the photo, species and handle.
- [ ] Given a group-only catch link, then the preview is the generic brand image and the page is 404 for outsiders.
- [ ] Given a signed-out visitor from a share link, then `share_opens` increases by one and they see the sign-up banner.

### Tests
- Integration: OG route for public vs non-public; counter.
- E2E (J7): signed-out visit to a public catch shows the page and banner.

## S-39 · Enter an official public challenge

**Type** Story · **Milestone** M5 · **Workstream** B · Gamification · **Priority** Should · **Size** M · **Journey** J6
**Depends on** {{S-27}}, {{S-28}}, {{S-08}} · **Blocks** nothing

### Story
As a competitive angler, I want to enter the platform's monthly challenge, so that I can compete beyond my group.

### Context
Proof grows with the audience: strangers compete here, so only catches whose photo the AI matched to the species count, reused photos are flagged, and reports can freeze an entry. During piracema (roughly November to February in much of Brazil), official challenges target pay-to-fish lakes, the sea, or released fish only.

### Implementation notes
- Official challenges: `scope = 'official'`, `group_id` null, `min_verification = 'photo_ai_match'`, created by platform admins at `/admin/challenges/new` (same form as S-26).
- Validation rule: if the dates overlap November–February, the filters must be `waterTypes ⊆ {pay_to_fish, sea}` or `releasedOnly = true`; otherwise reject with a message explaining piracema.
- Table `challenge_participants` (`challenge_id`, `user_id`, `joined_at`); "Participar" button on `/challenges` (a list of official challenges for everyone, plus my groups' challenges).
- Duplicate photos: when a catch is logged, compare its first photo's `phash` with other users' media (Hamming distance ≤ 6, checked with a bit-count query over hashes in the same species, or all hashes if small); if found, set `catches.duplicate_photo = true` and log it. Duplicates never count in official challenges.
- Frozen entries: a catch whose post has 3 counted reports is excluded until an admin restores it (reuses S-28's `hidden_at`).
- Scoring reuses `scoreChallenge` with participants instead of group members and the public visibility rule (a catch counts in an official challenge only if its post is public).

### Acceptance criteria
- [ ] Given a public catch with `photo_ai_match`, then it counts; with `reported`, it doesn't, and the leaderboard explains why in my own entry.
- [ ] Given the same photo logged by two accounts, then the second is flagged and excluded.
- [ ] Given an official challenge for December on rivers with kept fish, then creation is refused with the piracema message.

### Tests
- Unit: piracema validation; Hamming distance helper.
- Integration: scoring with verification, duplicate and frozen exclusions.
- E2E (J6): join, log a verified public catch, see it on the leaderboard.

## S-40 · Follow anglers and see a following feed

**Type** Story · **Milestone** M5 · **Workstream** C · Social · **Priority** Should · **Size** M · **Journey** J5
**Depends on** {{S-24}}, {{S-25}} · **Blocks** nothing

### Story
As an angler, I want to follow people I don't know personally, so that I see their public catches.

### Implementation notes
- Table `follows` (`follower_id`, `followee_id`, `created_at`; PK on both; index on `followee_id`).
- Commands `social.follow`, `social.unfollow` (rate limit 100 per day; can't follow yourself); `follow` emits `Followed` (S-30 notifies).
- `TimelineSource` scope `following`: posts where `author_id = any(followees)` and (`is_public` or shared to a group the viewer is in), ordered by (`created_at`, `id`) desc. Index `posts (author_id, created_at desc)`.
- Follow button on profiles (S-25) with the follower count; "Seguindo" tab on `/feed` with an empty state suggesting public profiles from the public feed.
- No follow requests; following is one-way and public.

### Acceptance criteria
- [ ] Given I follow someone, then their public catches appear in "Seguindo", and their group-only catches appear only if we share that group.
- [ ] Given I unfollow, then their posts leave the tab.

### Tests
- Integration: following scope visibility; self-follow refused.

## S-42 · Reward animation and sea moments

**Type** Story · **Milestone** M5 · **Workstream** C · Social · **Priority** Should · **Size** M · **Journey** J2
**Depends on** {{S-17}}, {{S-14}} · **Blocks** nothing

### Story
As an angler, I want the reward moment to feel alive, so that each catch is worth celebrating.

### Context
The animated sea appears only in special moments: the reward screen, the album, onboarding and empty states. Feeds and forms stay calm, for focus and battery.

### Implementation notes
- `src/ui/SeaScene.tsx`: a light SVG/CSS scene (water gradient from `sea-shallow`, a few fish silhouettes in `sea-deep` drifting, bubbles rising), at most ~10 animated elements, paused when off-screen (`IntersectionObserver`) or when the tab is hidden; loaded lazily.
- Reward sequence on `/log/done` (total under 1.5 s, tap to skip): sticker drops onto a paper card (300 ms, ease-out), sheen crosses raro and épico stickers (600 ms), XP counts up (600 ms), ranking line fades in.
- `prefers-reduced-motion: reduce`: no movement at all; the end state shows immediately.
- Budget: no layout shifts; the reward screen stays above 55 fps on a mid-range Android (check with Chrome's performance panel and note it in the PR).

### Acceptance criteria
- [ ] Given a new épico sticker, then the drop, sheen and count-up play once and can be skipped with a tap.
- [ ] Given reduced motion, then nothing moves and everything is visible.
- [ ] Given the feed, then no sea animation runs there.

### Tests
- E2E: reward screen with reduced motion emulated shows the final state immediately.
