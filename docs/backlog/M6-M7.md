## S-44 · Demo environment seed and reset

**Type** Task · **Milestone** M6 · **Workstream** B · Gamification · **Priority** Must · **Size** M
**Depends on** {{S-27}}, {{S-14}}, {{S-16}} · **Blocks** {{S-45}}

### Summary
A believable, clearly labeled demo that can be reset before recording and before judging.

### Implementation notes
- `scripts/seed-demo.ts` refuses to run unless `APP_ENV=demo` (or `local`). Deterministic (fixed random seed), so every reset looks the same.
- Content: 12 invented anglers with Brazilian names and avatars generated from initials; two groups ("Turma do Tietê", "Pesqueiro do Zé"); about 80 catches spread over the current season across 25 species, pay-to-fish and river, some released; stories and tips; reactions and comments; one active group challenge and one finished; an official challenge; rankings with close races.
- A juror account (`jurado@<domain>`, password in the README's demo section) placed in both groups, at level 4, with an album half full and a catch ready to log (a photo file in `scripts/demo-assets/` for the jury to try).
- Photos: the team's own or openly licensed (CC0 or CC BY with credit); each file and its source and license listed in `HACKATHON_COMPLIANCE.md`. No real people's faces unless they agreed.
- Catches are created through the real commands, then `replay-all` builds the ledger, so the gamification state is genuine.
- `scripts/reset-demo.ts`: truncate app tables (not `species`, `seasons`, `places` seed), delete the demo storage prefix, re-run the seed.
- A thin banner in the demo environment: "Ambiente de demonstração · dados fictícios".

### Acceptance criteria
- [ ] Given `reset-demo`, then the demo returns to the same state in under 5 minutes.
- [ ] Given the juror account, then logging the sample photo shows a new sticker, XP and a ranking move.
- [ ] Given the full Playwright suite run against the demo, then it passes.
- [ ] Given any demo photo, then its source and license are in the compliance file.
